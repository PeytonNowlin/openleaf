# OpenLeaf promo video

The ~65s 1080p30 cut embedded in the root README. Every product frame is the
real built bundle running in Chromium -- nothing in the editor shots is a mockup.

Frames are rendered one screenshot per output frame rather than screen-recorded.
Playwright's video recorder delivers a flat 25fps, which a 30fps assembly then
resamples by duplicating frames unevenly, and typing changes the screen faster
than 25fps can sample it; both showed up as judder. Nothing here runs on
wall-clock time, so the output is genuinely constant-frame-rate.

```
serve.mjs      static server: repo root + this dir under /promo
stage.html     the 1080p set: dark frame, app window, caption line, title cards
capture.mjs    drives the stage with Playwright, one video file per shot
assemble.mjs   normalizes every clip, crossfades them, writes out/
ai/BRIEF.md    the two generated bookend shots and the Higgsfield commands
shots/         captured product footage (regenerated by capture.mjs)
out/           openleaf-promo.mp4 + .webm
```

## Rebuild

```sh
node serve.mjs &        # port 4890
node capture.mjs        # ~90s, prints "clean" per shot
node assemble.mjs
```

The capture imports the repo's own `@playwright/test`, so the shots run against
the same browser build the e2e suite does. `shots/`, `out/` and `.frames/` are
build artifacts and gitignored -- the published video is committed at
`../assets/openleaf-promo.mp4`, and the README embeds it from there.

## Editing the cut

Shot order is file-name order across `ai/` and `shots/` together, so a clip
dropped in as `ai/00-*.mp4` opens the video and `ai/08-*.mp4` closes it with no
change to `assemble.mjs`.

Captions live in `capture.mjs` next to the actions they describe. Keep the claims
checkable: `19 KB` for the tables plugin and `121 KB gzipped` for the core are
this checkout's real measured gzip sizes, not round numbers.

There is no audio track. A muted README embed is what this is for; add a music
bed at assembly time if the video is going somewhere that expects sound.

The cut deliberately does not fade in. GitHub's markdown sanitizer strips
`poster` from a README `<video>`, so the thumbnail is frame one, and a fade from
black makes that a black rectangle.
